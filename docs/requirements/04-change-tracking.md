# Change tracking (audit)

> Part of the [requirements set](README.md). IDs are stable — tasks and tests reference them.

- FR-H1 Every change to folders, documents, versions, nodes, node content, permissions and comments is recorded: who, when, what (old and new values).
- FR-H2 A `User` entity is introduced; for now users are a **hardcoded seed** in the database (no real authentication).
- FR-H3 Data may be changed directly in the database by the **support team via SQL scripts**. Such changes **must also be captured** in the change log, marked as script changes, with the DB login and an optional ticket/reason.
- FR-H4 The change history is available **for every node/section inside the document editor**: per-section change indicators, an inline per-section timeline (across versions, including script changes), viewing and restoring an earlier state, and **track changes in the section text**: insertions, deletions and formatting changes against a chosen baseline (latest signed version, any version, or a date), each change attributed to its author and time. The API provides the per-node history, a per-version change summary, historical content, and an attributed diff.
- FR-H6 **Tamper evidence against privileged principals** (DBA, `dbo`, the deployment pipeline): changes that bypass the audit triggers, forged audit rows and rewritten history are detected, recorded as findings visible to admins (Admin → Audit), and mark the affected versions as tampered (T21, decisions log Q18).
- FR-H5 **[A]** If a Signed version is modified by a script after signing, the system detects it and flags the version as "modified after signing": the flag is `app.VersionStamp.TamperedAt IS NOT NULL` (set by the audit triggers on the first such change) **or** a reconciliation finding committed at or after the signing transaction (taken from the ledger, not from the editable `SignedAt` column; a bypass that itself signed the version counts) exists for the version (T21 — so a cleared stamp keeps the flag; findings from before signing don't count); only Signed versions carry the flag. A hash comparison against `SignedContentHash` additionally tells whether the content still differs.
